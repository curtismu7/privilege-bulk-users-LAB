- **Where the role lives, and which route to use.** The Guide (model section, step 0, route B row), the README and `docs/live-checks.md` now say that Privilege only reads people from PingOne, that the Identity Data Admin role is set on the PingOne worker app (the Privilege app has no role to set), and that route B, the only route that writes into Privilege itself, has never run against a real console and may not work. The Guide and README also say, up front, that Privilege can take the user and the groups from token claims (any claim, for example a PingFederate token; part of Privilege's OBO setup) instead of from PingOne, so there may be nobody to register; how that is set up is listed as UNVERIFIED. Wording only: no behaviour changed.

- **The shared JsonPane (rule 24, amended 2026-11-14).** Every JSON pane (the Guide's excerpts, a row's detail, an audit entry) now renders through the shared `JsonPane` (a Formatted form by default, with a Raw toggle), vendored byte for byte with its stylesheet and sha256 pins. It replaces the old `JsonView`, which is gone from the canonical shared folder. Control, bidi and zero-width characters still show as escapes in both views (`web/src/safeText.js` hands the lab's `visible()` to it).
- **The circuit breaker judges a window.** It looks at the most recent 50 results (once 20 have finished), not the whole run, so a long run that breaks half way stops promptly instead of needing hundreds of failures. A run of 50 people or fewer behaves as before. A stop by the user that came first is never turned into a `circuit_open` by the results still arriving from calls in flight.
- **Matching folds ASCII only.** `toLowerCase()` folded look-alikes such as the Kelvin sign (U+212A) onto plain letters, which could match a person to somebody else's account and add that account to the Privilege group. Email and username matching now folds the ASCII letters only (`server/src/fold.js`), in the plan, the route-B listing and the lookup after a lost create answer.
- **An unsupported `Content-Encoding` or charset is a 415** (`unsupported_media`, fixed text), not a 500.
- **Wider accessibility coverage in `npm run e2e`.** axe now also runs on the Audit page (the JSON pane in both views), the Diagram page and the Help page.

## 0.1.0 (unreleased): first version

A new standalone lab, forked from [privilege-api-explorer-LAB](https://github.com/curtismu7/privilege-api-explorer-LAB): its own repo, port, shelf entry, content pack and history. The explorer's connections store and catalog explorer are gone; everything below is new.

- **The bulk engine.** One job at a time, a plan (reads, decides, writes nothing) or an apply (writes from a plan), and a verify that is a second plan. Read the source once, snapshot the destination once, decide every person in memory (create and add, add, in sync, conflict, invalid), apply through a bounded pool (1 to 16, default 6) and stop on purpose (a circuit breaker) when most of the first people fail.
- **Two routes.** Route A registers people through the PingOne Management API (create in Privilege's environment with no password, add to the Privilege group, retry the add for a person created a moment ago). Route B creates user records with the Privilege console API (`POST /v1/users`) and is UNVERIFIED against a real console.
- **A resilient request path.** One shared gate: a 429 pauses every worker for the `Retry-After` (seconds or a date, capped), a 5xx or a network error is retried with back-off, and one bad person is one failed row. The Run page shows the 429 count and the time waited.
- **The two-step gate.** Apply needs a fresh plan, the exact count typed back (`REGISTER <n>`), every blocking warning acknowledged (an empty destination list is `destination_empty`, the Identity Data Admin trap) and, in Real, the Writes switch. Every refusal is a named JSON code. This lab never deletes.
- **The Mock world.** A deterministic in-process stand-in for PingOne and the Privilege console with made-up people, six scenarios (realistic, clean, rate-limited, flaky, conflicts, missing role) and a ground truth the tests compare the plan with. No socket opens.
- **Pages.** Guide (route A as `curl` commands with `$PLACEHOLDER` variables, the UNVERIFIED list), Run (plan, apply, verify, counts, results table, JSON and CSV reports), Diagram (route-a and route-b as diagram-studio data), Audit, Help.
- **Settings** come from this lab's own `.env` beside `docker-compose.yml` (names in `.env.example`, pinned to `SETTING_KEYS` and `docs/api.md` by a test); Real is refused unless `PRIVILEGE_BULK_MODE=real` is set there. Compose reads it through an optional `env_file`, so Mock needs no file.
- **Packaging.** Port 7817 (loopback only), Node 26 only, Docker on OrbStack (non-root, read-only, `restart: unless-stopped`), `npm run doctor`, `reset`, `smoke`, `verify-running` and `e2e` (headless Chromium on 7998; the Vite dev server is 7999), a Learning Hub content pack (`demo-content-pack/1`), a presenter talk track, a shelf entry with no catalog id yet (the owner assigns one), CI with docker (the image builds, compose is valid with no `.env`), forbidden-strings, gitleaks, AI-attribution and end-to-end jobs. The image has the wide bind but not the container marker: only compose, with its `127.0.0.1` publish, lets Real run in Docker, and a bare `docker run` refuses it. `.env` files are ignored at any depth by git and Docker; `.env.example` stays tracked.
- **Identity.** Nothing of the explorer's identity is left: its port, catalog id, environment prefix, mode key, connection store and spec catalog are gone, and a test scans the repo for them.
- **Not verified.** Nothing in Real was run while this lab was built. See `docs/references.md` and `docs/live-checks.md`.
